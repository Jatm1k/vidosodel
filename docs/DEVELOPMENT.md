# Разработка Vidosodel

## Ветки

| Ветка | Назначение |
|---|---|
| `main` | Стабильная. Копии пользователей смотрят сюда, сюда попадают **только релизы** (её двигает `scripts/release.py`). Напрямую в `main` не коммитим. |
| `dev` | Рабочая. Сюда вливаются готовые изменения. |
| `feat/…`, `fix/…` | Для крупных задач: ответвляемся от `dev`, по готовности вливаем обратно. Мелкое можно коммитить прямо в `dev`. |

## Коммиты

Формат [Conventional Commits](https://www.conventionalcommits.org/ru/): `тип: что сделано`, по-русски.

- `feat:` — новая возможность (→ минорная версия);
- `fix:` — исправление (→ патч);
- `refactor:`, `perf:`, `docs:`, `chore:` — без изменений для пользователя;
- `feat!:` или строка `BREAKING CHANGE:` в описании — несовместимое изменение (→ мажорная версия).

Пример: `feat: распределение моделей картинок по бюджету проекта`.

## Журнал изменений

Каждое изменение, которое заметит пользователь, сразу дописывается в раздел `## [Unreleased]`
файла `CHANGELOG.md` — в тот же коммит. Подразделы: «Добавлено», «Изменено», «Исправлено», «Удалено»
(или тематические, как в 1.0.0). Пишем для пользователя: что изменилось и что это даёт.
Этот текст показывается в окне обновления.

## Версии

Единственный источник версии — файл `VERSION` (`МАЖОРНАЯ.МИНОРНАЯ.ПАТЧ`). Его читают
бэкенд (`backend/app/version.py`), лаунчер и интерфейс. Вручную не правим — только через релиз.

## Релиз

```
git checkout dev
python scripts/release.py minor --dry-run   # проверить, что войдёт
python scripts/release.py minor --push      # patch | minor | major | X.Y.Z
```

Скрипт проверит, что всё закоммичено и раздел Unreleased не пуст, перенесёт его в новую версию,
обновит `VERSION` и `frontend/package.json`, пересоберёт `frontend/dist` (он в репозитории, чтобы
пользователям не нужен был Node.js), сделает коммит `release: vX.Y.Z`, тег `vX.Y.Z`, передвинет
`main` на релиз и (с `--push`) отправит `dev`, `main` и тег на GitHub.

## Как обновляются пользователи

- **При запуске** `start.bat` / `start.sh` делают `git fetch` и, если в `main` есть новая версия,
  показывают её изменения из `CHANGELOG.md` и спрашивают: обновить / нет / пропустить эту версию.
  После `git pull` лаунчер перезапускается сам: зависимости и интерфейс обновятся по необходимости.
- **Во время работы** сервер раз в 6 часов проверяет обновления; в боковой панели появляется
  «Доступна версия X» с кнопкой «Обновить и перезапустить».
- Автообновление не трогает копию, если в файлах программы есть локальные правки или локальные
  коммиты — тогда показывается подсказка, как обновиться вручную. Данные (`data/`), ключи (`.env`)
  и скачанные инструменты (`tools/`) в git не входят и при обновлении не меняются.
- Проверку можно отключить: `start.bat --no-update-check` или `VIDOSODEL_NO_UPDATE_CHECK=1`.

## Запуск для разработки

```
cd backend && ../.venv/Scripts/python -m app      # API на :8765
cd frontend && npm install && npm run dev         # UI на :5173 с прокси к API
cd frontend && npm run typecheck                  # проверка типов
```

Данные: `data/` (база `vidosodel.db`, медиа, свои шрифты для субтитров в `data/fonts`).
